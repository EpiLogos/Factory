# Bounded agency foundation

Standing: implementation account and remaining design obligations, 2026-09-06. The experience-governance statement remains a human-ground proposal. This document does not adopt it or turn an acceptance fixture into a production deployment.

The Factory owns a reduced developmental Method in `skills/factory-bounded-work`. AIKit composes its three source-owned Skills and resolves the native Method. The desktop connection remains AIKit's resident ACP owner → `AgentSessionHost` → `pi-acp` → Pi. Workcell owns the material operation; Factory receives the Candidate and evidence. There is no pstack scheduler, independent agency ledger or competing direct Pi RPC client.

[Factory Mode](../../agents/factory-mode/README.md) supplies the source expression and native `profile/factory-mode` for this foundation. Commissioned profiles derive from it with explicit lineage and situated bounds. Future QL–MEF Anima and Aletheia expressions can build on the same Method and source relations.

## The law in its operative form

Respect for experience concerns the conditions through which an intention becomes possible to live. The technical consequence is to preserve the meaning and bounds of that intention through each owner passage, and to preserve the return through which the result can correct the form. The six movements below articulate that responsibility; they are not a new runtime schema.

## Source reduction and invocation

The upstream is the MIT-licensed `pstack` plugin at revision `93b00b89ef425a9c1bac0d0b317dfc49c930ac99`. Its clean checkout stays a reference. [The source account](../pstack-reduction/source-accounting.md), [edge account](../pstack-reduction/edge-accounting.md) and [reduced Mermaid graph](../pstack-reduction/reduced-map.mmd) expose how each prompt and source relation is handled. Textual mentions are candidates for interpretation, never an observed call trace.

The maintained core is deliberately small: recover the concern; choose a verifiable unit; investigate or change; verify actual behavior; return attributable evidence. Repair, change and coordination procedures load conditionally. Existing `factory-development` and `factory-operation` retain their whole-work and native-operation offices. Upstream persona, unconditional publication and kill-on-doubt policies do not acquire authority through import. Optional families retain their source account until a native destination and a real need warrant adoption.

## Repeatable native acceptance

`scripts/verify_bounded_skill_source.py` exercises the real AIKit source lifecycle in a temporary AIKit home: discovery, immutable promotion, exact SkillSet membership, missing-member refusal and recovery. It never changes the user's active source registry.

`scripts/verify_acp_bounded_work.py` uses explicit native binaries and configured provider credentials to run one real Pi proposal over ACP. It first executes a real failing pricing function, preserves selected source bytes and the delivered prompt, and requires an actual completed native answer. It does not invent provider output or let the model apply the repair.

The native integration harness in O:I at `tests/agency-bounded-acp` consumes that retained proposal. Its fixed Workcell operation checks admissible Python syntax and actual numeric behavior, atomically writes once, then rejects replay. Its Factory return operation verifies the retained ACP/context/material evidence, observes the actual repaired artifact, persists native evidence and Return, and demonstrates stale applicability without changing the accepted history.

`scripts/verify_acp_material.py` runs that material stage from the real ACP evidence. It tests required-source absence/change and primary owner-source changes before the successful operation; the native helper re-observes the pinned basis immediately before dispatch. Exact argv/cwd authority, revocation, expiry and consumption remain Workcell decisions. This local observation is not an atomic source lock or a replacement for source-owner resolution.

The first observed circuit is retained in Central's root NOW field at `Control/agents/now/agents/experience-law-pstack/acp-bounded-live`. That first invocation explicitly has no issued native Method/ContextResolution binding. Later richer receipts must remain separate rather than retrospectively altering its basis.

## Next native obligations

The richer observed circuit at `acp-composed-live-framed` issued native Method/ContextResolution and Central/Actuation/AIKit source composition before launch, matched the ACP-reported model, and retained typed JourneyPraxisReturn after real material application. Changed primary owner sources were refused before dispatch. MethodProof and human Recognition remain absent; the V2 model catalog did not gain availability merely from a requested model ref.

The executable foundation must continue through real owner seams. Source observations need a coherent basis within each composition, and materially concurrent writers require stronger source/snapshot ownership than the bounded pre-dispatch observation used here. Dynamic tool requests must be correlated to the exact Actuation decision and Workcell operation; ACP provider consent alone cannot supply that decision.

Plurality then requires an explicit useful plural commission, one writer per shared subject, aggregate consumption and retry limits, durable spent/revoked authority across restart, and admission of late output against the original invocation and current subject. A second worker is justified by independent work, not by a role appearing in a prompt. Grok's seed/daemon influences and Buzz's activity/attention distinctions inform these obligations; provider parity must be demonstrated on each actual runtime.

The final passage is into the existing desktop Encounter and Factory surfaces: useful progress, actual decision need, interruption and accountable return must remain intelligible. A technically accepted artifact can still ask for a better experience. The structure must keep that challenge able to reach its responsible owner.
