## 0. The ownership correction

**TypeScript workflow/run authoring is base Factory functionality.** Factory owns the public typed authoring interface, generic schema/validation, deterministic lowering into its workflow source, compiled WorkflowUnit identity, source-to-Commission/Run attachment and public source/topology/attempt correlation. It is usable without QL-MEF, Ta-Onta, Epi-Logos, Claude or an Expression renderer.

QL-MEF and Epi-Logos remain optional, source-qualified interpretations/projections through that technology. A Vāk-authored undertaking uses the same Factory authoring and execution route with its explicit domain binding. QL owns the meaning of C′ and its role/sequence/musical interpretation, not the generic TypeScript entry, source stamp or Run authoring lifecycle. Ta-Onta's constitutional/specialist cast is one domain's selected participant field, not Factory's built-in roster.

This corrects the narrower reading in QL-MEF #233 / O:I #401 that placed the first TypeScript frontend under Vāk. The ordinary typed workflow capability was already assigned to Factory #197; this document makes its full landing and UI/trajectory consequences explicit.

```text
ordinary request, existing source, or typed authoring
  → Factory-owned TypeScript workflow source interface
  → deterministic native WorkflowSource / CompiledWorkflow
  → first authored source basis on the Commission / Run
  → RunMap / Execution Intelligence / ExecutionDisposition
  → actual Agency, context, harness/session and material execution
  → Activity, native trace, artifacts, verification and Return
  → Factory public read/Action projections
  → SSSF-derived Build, TUI, structured agent and O:I consumers

optional QL / Vāk / another paradigm
  ↔ qualified authored interpretation, role selection and lawful conduct
  ↔ the same native source, unit, Run, attempt and evidence identities
```

Projection is not restricted to cosmetic annotation: an explicitly selected interpretation can determine native dependencies, role requirements, effects or passage through the existing validated orchestration contract. Its influence and version remain attributable. It must not become another Run, dispatcher or source owner.

## 1. Authoring is useful before a paradigm is selected

> I describe the work or open its workflow source. I can understand the required difference, which collaborators and powers are needed, what can happen together, and what must return. I can run it, inspect how the actual execution compares with that definition, and revise the next undertaking without rewriting the first one.

A person need not write TypeScript to commission work; an agent or supported source editor can prepare it. The source remains inspectable and editable through native file/document operations. A simple one-agent workflow remains simple. Parallelism, barriers, independent judgement and nesting are used where the concern requires them, not imposed as a six-stage template.

The generic definition retains the already-authored #197 fields: concern, required difference, subject/basis, participant requirements, praxis/capability requirements, dependencies and independence, effects, verification, return address, stop/escalation conditions, barriers and nesting. Role descriptions must say what a participant contributes, the inputs/context it needs and the result it is responsible for. Native Agent/AgentSet/Agency identities are references from their owners, not invented by the authoring library or copied from a display name.

Runtime body/model choice is a requirement or policy until actual resolution. A TypeScript participant declaration is not a launched agent, a tool allowlist is not a grant, and a declared verifier is not independent verification until its actual role/context/execution is established. Preserve generic task roles and arbitrary legitimate native participants; no universal Nous/Logos/etc requirement.

A conventional `*.workflow.ts` filename may identify the ordinary source. `*.vak.ts` may identify a domain-authored example. Filename spelling is not native identity, execution authority or evidence that a new loader exists. Reuse an existing compatible authoring path and publish its actual entry; this plan does not invent an npm package or unregistered command.

## 2. Native source and deterministic compilation

The existing owners to extend or consume are:

- `factory/src/workflow.rs`: `factory.agent-workflow-source/v1`, `WorkflowSourceProvenance`, `AgentRequirements`, `WorkflowUnitSource`, `CompiledWorkflow`, stable unit identity and source digest.
- `factory/src/orchestration.rs` and native attempt modules: actual delegation, launch, barriers, retries, late results, cancellation and Return.
- `factory/src/developmental_read.rs`, `build.rs`, `build_provider.rs` and their published successors: source-qualified native read/Action projection.
- `factory/src/vak_orchestration/`: optional C′-qualified conduct against those generic owners, not a replacement compiler/runner.

Reinspect exact current source before implementation. The presence of these Rust modules does not alone prove a shipped TypeScript SDK or public authoring route. A prior closed issue is preserved as scoped accepted work, not used to hide a missing frontend or justify rebuilding its compiler.

Factory publishes or contract-checks TypeScript types against the owning native schema. Do not create a hand-maintained parallel ontology in QL, O:I or a Claude adapter. A domain type layer imports/composes the generic types and attaches source-qualified meaning via existing extension points. Add a missing extension field only at the correct owner with compatibility tests.

The authoring input is restricted data/builders and approved deterministic imports, not arbitrary code executed in the desktop or with the person's credentials. Validation/lowering itself causes no model invocation, file mutation beyond its declared output, dispatch or publication. Reuse the existing material isolation when build-time execution is actually necessary and authorised; declare inputs, bound resources, and exclude implicit clock/random/network/environment changes from semantic compilation.

Preserve the authored bytes/revision and transitive import/compiler basis separately from the canonical semantic digest. Formatting may change source revision without changing semantic unit identity. Execution-relevant edits must change the relevant basis. The current native identity algorithm, not a TypeScript AST node, line number, display order, provider job or trace span, determines the unit.

## 3. The first source stamp belongs to Factory

Before the first admitted effect, attach the actual authored source basis to the existing Commission/Run provenance. Inspect existing fields first; extend them only for demonstrated missing information, not by building a second stamp database.

Retain source ref/revision and source/import digest, compiler/schema basis, compiled workflow/unit refs and semantic digest, subject/revision, participant and capability requirements, effects, dependencies/barriers, proof/Return and bounds. Optional interpretation refs/revisions are additional qualified source basis. A generic workflow has no mandatory QL field or QL lookup.

This is the first **authored workflow basis**, not a fabricated earlier runtime event or the identity of a Run. A draft can precede a Run. An existing Run can record an explicitly admitted workflow revision without losing its earlier activity. If old work lacks a source stamp, report that absence rather than retroactively certifying it.

At execution, separately record resolved Agent/Agency, context/praxis, body/model, session, Workcell, authority and attempt identity. Intention and actuality must remain comparable, not overwrite one another. A model/provider change or retry does not replace the semantic unit; every attempt remains independently attributable.

Replan/recomposition creates an explicit successor basis or bounded continuation using the current native lifecycle. Human/source edits during work do not silently change its effective definition. The next attempt names the admitted basis; held historical inspection still shows the old one. Source rollback never claims to undo already-performed effects.

## 4. SSSF and the human/agent authoring loop

Retain the [SSSF source-fidelity record](../GUI-SSSF-SOURCE-FIDELITY.md) and #145 semantic/live/trajectory distinction. The UI does not become a TypeScript IDE requirement or a new authoring ontology. It presents the same native definition and execution through the owner's current app arrangement.

| Depth | Required native reading and interaction |
|---|---|
| Intended work | Concern, expected difference, source revision, selected participants, dependencies, effects and proof/Return; open exact source and useful validation error locations. |
| Compiled topology | Actual WorkflowUnit/RunMap refs and barriers, including waiting/failed/missing legs; select a source unit and highlight its compiled/executing counterpart. |
| Live world | Actual participating Agency/session/body/model/material bindings and current availability, distinct from source requirements. |
| Trajectory | Attempt-specific model/tool/process/permission events, native cursor/order, arguments/results/error, durations and evidence where supplied. |
| Return | Produced material and its source/attempt basis, verification, contradictions, pending decisions and explicit later revision/continuation. |

Required traversal: **source definition → compiled unit → Run/frontier → execution attempt → actual trajectory/tool result → produced evidence → source basis again**. The reverse traversal must also resolve. Multiple attempts do not collapse into one source node, and a timeline phase does not become the unit's canonical identity.

Maintain the current O:I handoff: **Desk / Tasks** in the centre, **Run / Agents / Context** alongside. Desk exposes the Run board and selected full SSSF view; Tasks exposes the actual working conversation. Run offers control/trajectory and source-basis inspection; Agents resolves participants and their faculties; Context contains the actual authored inputs and produced work. Substantial source or trace detail can open through existing panes/popouts. This is capability placement for the approved UI, not permission to overwrite its layout or return to an old six-tab console.

Keep useful names and outcomes foremost, with exact refs, source locations, graphs and event detail available progressively. Show planned versus acting versus stopped/unknown distinctly. A source compilation error should identify its unit/field, violated rule and next correction; a provider failure should not masquerade as a malformed workflow.

GUI, TUI and structured agent routes consume the same Factory-owned read/Action contract. TUI need not imitate graphical geometry. The new parallel UI is the landing destination; a donor-app or native-only test must retain its actual evidence scope.

## 5. DSH and native log tracking

DeepSeek Harness (DSH) remains a rich native harness/trajectory specimen, not a required Factory runtime. When an execution actually uses DSH, preserve its native SessionEvent/trajectory and available HarnessComposition fingerprint through the accepted Actuation/AIKit adapters. When another harness runs, preserve its native evidence and disclose unavailable richer fields. DSH-inspired readable detail is available as UI design without requiring DSH installation.

Correlate where actually established:

```text
workflow source + revision/digest + source unit locator
  ↔ WorkflowUnitRef / JourneyRef / RunRef
  ↔ ExecutionDisposition / Execution / attempt
  ↔ Agent / Agency / ActuationStream Activity
  ↔ model/provider + effective context/praxis
  ↔ Harness / AgentSession / native session + trace/span/event refs
  ↔ Workcell + root/child NOW + Flow/source/Git basis
  ↔ artifact / verification / Evidence / Return
```

Factory owns the developmental correlation, not a copied DSH log database or universal observability service. Actuation owns agency/activity observations; AIKit owns body/session/context resolution; Workcell supplies material facts; Central owns temporal/source identity; O:I hosts the human presentation. A stream and each native trace keep their own owner cursor and chronology, with occurrence and receipt time distinct. Do not invent a global total order for independent streams.

Preserve start, completion, tool call/result, permissions, child handoff, errors, retry/cancellation and late events at their supported scope. Idempotent ingestion/reconnect must not duplicate effects or erase gaps. Cancellation requested, accepted, process stopped and quiescent remain different observations. Historical/external work is correlated only when binding evidence exists, not retrospectively labelled a Factory execution from process name.

Model/token/cache/cost/material readings retain provenance and reported/derived/unknown standing. Workflow source does not contain fabricated performance claims. Payloads are bounded/lazy/paginated, unavailable detail is explicit, sensitive inputs are protected before disclosure, and inspecting history suspends auto-follow without stealing selection. A receipt or span without the actual native effect is not execution proof.

Optional QL/musical/observer readings are attached to this same source/trajectory basis and can be opened or omitted. A no-QL run retains the complete source, SSSF and native-log experience.

## 7. Discriminating acceptance

First prove **no-QL/no-Epi** ordinary work: author and validate a generic TS workflow, inspect its exact basis before dispatch, perform real work, traverse source→SSSF unit→attempt→native tool event→result, and return to the same source. No invented QL registry, role names, authoring package or mandatory seven-agent cast may be needed.

Then prove an optional Vāk-authored Expression undertaking over the same generic contracts: selected C′ changes the intended conduct, with qualified domain provenance, while core Run/unit/attempt and native trace ownership remain unchanged. Removing optional display readings must not remove generic evidence; executing an explicitly required unavailable semantic interpretation must be honestly withheld, not silently stripped.

Include formatting versus semantic changes; changed imports; invalid dependencies; missing participant or tool; denied effects; stale source/admission; two concurrent units; actual selected predecessor material; failed required leg; independent verification; retry on a new attempt; late/cancelled events; interruption and re-entry; trace pagination/reconnect; human source edit during execution; and explicit successor workflow revision. Test both directions of source/trace navigation and held versus live state.

DSH maximal and one thinner native path retain different coverage. Use real DSH where admitted/available to prove DSH-native integration; a fixture is contract evidence only. Generic source/SSSF/log work must succeed with DSH absent. No UI screenshot, typed declaration, valid receipt or function-level mock stands in for the complete public operation.

A first-source stamp is authored intention, not a success result. New source after failure must preserve original evidence, and the independent verifier must reject a disconnected handler, wrong-source/attempt response or a fake completed status. Machine proof and actual human judgement remain distinct; no premature Recognition gate blocks construction.

**Completion:** an ordinary person/agent can define and run work in base Factory, see what was meant beside what actually happened in the existing SSSF/trace experience, and revise or continue with exact lineage. QL/Vāk/Epi enrich that same technology rather than owning or gating it.
